# WG16 — Full Project Audit (2026-06-21)

A point-in-time, read-only audit of the whole project. **Method:** 7 parallel subsystem
deep-dives, each finding adversarially re-verified by an independent agent against the actual
code, cross-checked against a first-hand read of the newest (atmosphere) code and a clean
compile. Where verification *changed* a finding's severity, the corrected version is recorded
here — not the original claim. 61 findings total (16 bad / 18 ugly / 8 gap / 19 good); 28
confirmed, 6 softened on verification, the good findings unchallenged.

**This is a snapshot, not a steering doc.** It does not supersede ROADMAP/NEEDS_REVIEW/DECISIONS;
it feeds them. Several findings below are themselves "reconcile the steering docs" items.

**Build health:** compiles clean — `dotnet build` → **0 errors**, ~48 warnings, all but 2 are
nullable-reference hygiene (CS8604/8600/8618/8602); 2 are member-hiding (CS0108). No blockers.

## 🪞 ME — the state of the project, honestly

A genuinely impressive amount of correct, AAA-leaning graphics tech has been built in a short
window: a faithful Hillaire 2020 physical-atmosphere LUT chain, amortized volumetric clouds with
matched shadow maps, a decoupled Time×Weather×Mood lighting composer, screen-space god rays, an
N-deck cloud system, night/celestial, and a froxel aerial-perspective pass — all on a hard GPU
seam (`CallOnRenderThread` + `Texture2Drd`, RID-assigned-once) that is correct in *every*
subsystem. The compute lifecycle discipline, the std430 packing via `Std430Writer`, and the
data-driven control registry are the strongest patterns in the codebase, and the verification
pass found **zero RID races, zero per-frame leaks, and zero silently-dead `param` controls** in
the active paths. The bones are AAA-capable.

Three structural/process truths to internalize before pushing further:

1. **The frame is already over budget, and the only real lever is parked.** In motion ~9.6 ms vs
   an 8 ms target — *before* flora/water/erosion/biomes — and ~7 ms of that is the single
   4.19M-vert un-LOD'd `PlaneMesh` (raster floor + SDFGI). Terrain LOD is the only fix that hits
   mesh+GI+shadow together, and it's parked behind the "clipmap killed WG1–15" graveyard. The
   honest conclusion, blunter than the docs state it: **8 ms with a world's worth of features is
   not reachable on the current single-mesh architecture.** A roadmap fact, not a bug.

2. **The "eye-gate discipline" is aspirational, not operational.** The 06-20 reset existed to stop
   "building three phases past the last gate." Within the same day — *with explicit
   user re-authorization* ("plan it all, make a roadmap, lets do it") — the sky lane shipped ~10
   sequential phases, and 4+ are still un-judged-by-eye (clouds CO-3/CO-4, AT-1 horizon-flash in
   motion, the *entire* AT-2 aerial pass), with Celestial C1 queued on top. Not a secret violation
   — authorized — but the rule as written describes a workflow not actually followed. Reconcile one
   to the other.

3. **A day of irreplaceable work lives only on this machine.** `experiment/presentation` is **179
   commits ahead of origin** (the whole post-reset sky system) and the 3 newest backup tags are
   local-only. Policy-compliant ("push only when asked") — but "git is the undo" has no off-machine
   copy right now.

The intended sequence — **finish atmosphere/sky, then textures** — is right. The audit's main
amendment: **run the combined eye-gate session first**, and do two cleanups (tile_mode + the
sky-color ownership question) before the texture lane goes live, or the same un-gated debt carries
into it.

## ✅ GOOD — genuinely strong, keep it

- **The render-thread compute seam is textbook, everywhere.** AT-1's four LUTs, AT-2's froxel, and
  the cloud raymarch/shadow all assign their `Texture2Drd`/`Texture3Drd` RID exactly once, cache
  uniform sets, update only buffer *contents* per frame, free on dispose. No `CompositorEffect`, no
  per-frame RID realloc, no leaks. (`AtmosphereCompute.cs:110`, `CloudVolume.cs`.)
- **std430 packing is drift-proof.** Every GPU param buffer goes through `Std430Writer`; field-by-
  field verification confirmed C# order matches the GLSL structs across all four cloud buffers and
  the atmosphere buffers. The packing-bug class that bit 3× ("no clouds") is structurally closed.
- **The physics is a faithful Hillaire port.** Transmittance → isotropic multi-scatter
  (ψ = lum/(1−fms) geometric series) → sky-view with correct rayPhase/miePhase. AT-2's composite is
  correct: `color·T + inscatter` on geometry only, sky gated out via reverse-Z depth, no
  double-count, real fog handoff (`aerial_screen.gdshader:47`).
- **The data-driven control registry is the best architectural idea here.** 64 param-mapped
  controls, **zero** that name a missing uniform; every scene/cloud applier target has a matching
  C# case.
- **The base field is untouched and clean.** `field_height.glsl` is the proven WG15 5-layer math
  with a 29-param ABI matching `field_params.json` field-for-field.
- **Material curation is coherent and leak-free.** 738 → 108 (verdicts: 625 fail / 108 pass / 5
  dropped), all 108 present on disk, GPU bakes (splat/height/histogram) mirror the proven local-RD
  readback pattern with correct invalidation.
- **Clouds dead-code hygiene is clean.** The superseded `FogVolume` god-ray path is *fully* removed.
  The one user-PASSED ground feature (histogram-preserving anti-tiling, Deliot-Heitz) is well-built.
- **God rays are a clean, additive, single-assign fullscreen pass** — no race, no leak, no
  per-frame material recompute. **`ComposeLighting` is a genuine single-writer**; the per-frame
  overcast tracker funnels through the same path and cannot fight it.

## ❌ BAD — real defects/risks (ranked)

1. **AT-1 *and* AT-2 are default-ON but never passed a live eye-gate — against the project's own
   rule.** [sev 4, confirmed] Both `atmosphere_on` and `aerial_on` are `default: true`
   (`lab_controls.json:158-160`) and replace the approved keyframed look by default. Neither is in
   the `NEEDS_REVIEW` queue; AT-2's live-gate step is an unchecked box; **AT-2 has zero measured
   frame cost anywhere in docs**, and `DECISIONS.md`'s newest entry says AT-2 was "NOT built this
   session" while the code has it built and on. AT-1 was "soft-passed" off cycling stills — which
   the pillars say is *not* a look gate. The approved look is one toggle away (`--atmosphere=0` /
   `--aerial=0`), so not catastrophic — but the default look was swapped un-judged.
2. **The architecture cannot hit the 8 ms budget.** [sev 4, confirmed] 9.6 ms in motion, ~4 ms
   mesh floor + ~2.9 ms SDFGI, on a no-LOD 4.19M-vert mesh, before a world's features. Only lever
   (CDLOD/chunking) is parked behind the clipmap post-mortem.
3. **Two parallel daytime-sky-color systems that silently disagree.** [sev 3 → RESOLVED 2026-06-21:
   re-investigation downgraded this to a *documentation* trap, not disagreeing systems.] With
   atmosphere on (the default), the physical LUT *replaces* the keyframed gradient in
   `cloud_sky.gdshader` — yet `ComposeLighting` still samples `day_script` and pushes
   `SetSkyColors(...)` every frame. **Tuning the day_script daytime palette does nothing visible** —
   a real art-direction trap. BUT: tracing `background()` shows the keyframed gradient is
   `mix(atmo, grad, night_factor)`, so the same push is **load-bearing for the NIGHT sky** + the
   atmosphere-off fallback — it is NOT a redundant/disagreeing daytime write, and removing it would
   break night. **Resolution:** no behavior change — the ownership law is now documented in
   `ComposeLighting` (atmosphere LUT owns the daytime sky/cloud-ambient; grade the day sky via
   `sky_tint`/atmo exposure; day_script daytime colors are by-design superseded). day_script-as-grade-
   over-LUT remains a *future look feature* (its own eye-gate), not a debt fix.
4. **Cloud detail-erosion diverges between raymarch and shadow.** [sev 3, confirmed] The raymarch
   erodes cloud edges harder (2-octave) than the shadow/shadow-check shaders (1-octave), so ground
   shadows are cast from fuller edges than rendered — and `--shadowcheck` is structurally blind to
   it (it matches the shadow shader, not the raymarch). Documented and deliberately deferred =
   accepted debt with an owed gate, not a hidden bug.
5. **`performance.md` is stale and now misleads the budget math.** [sev 3, confirmed] It headlines
   the GI/shadow proxy as "DEFAULT ON" and prices 9.6 ms accordingly — but the newer 0b decision
   flipped SDFGI **off** + proxy **off**, and code/scenes/registry agree (both `.tscn`
   `sdfgi_enabled=false`). A reader trusting the perf doc mis-attributes ~2.4 ms of SDFGI no longer
   paid by default.
6. **The texture lane's tile_mode dropdown has dead/lying options — live now.** [sev 3, confirmed]
   The "IQ 2-tap" / "hex-tiling" `tile_mode` options no longer do anything (paths retired), and
   `hex_contrast` has a live UI slider wired to a uniform referenced nowhere in the shader — a
   silent no-op. The entangled-cleanup trap (enum index == uniform value, Shift+3 harness) is real.
7. **179 commits ahead of origin; newest backup tags local-only.** [sev 3, confirmed] Entire sky
   lane exists only on this machine. (Materials are re-derivable; the source commits + tags are
   not.) One authorized push fixes it.
8. **`tools/copy_materials.py` regenerates all 738, not the 108, and silently no-ops if `D:\assets`
   is gone.** [sev 3, confirmed] Hardcoded `ROOTS=[r"D:\assets"]`, no `material_library.json`
   filter, exit 0 on missing drive. Fresh checkout = 2.5 GB of 625 rejected materials. Not
   data-loss (all 108 present today), but a repro/bloat + silent-failure footgun.
9. **`ComposeLighting` writes a `ProceduralSkyMaterial` the cloud sky already replaced** — a dead
   branch in steady state, gated out by a silent type-check. [sev 2, confirmed] Hides the coupling.
10. **Galaxy/Milky Way is a confirmed placeholder** — uniform fog band, dust lanes never carve to
    black. [sev 2, confirmed] Already queued as Celestial C1; not shippable as-is.
11. **`project.godot` boots the *frozen* `lab.tscn`, not the active `terrain_lab.tscn`.** [sev 2,
    confirmed] Cheap, high-signal drift.

## 🟡 UGLY — works, but debt/smell

- **`TerrainLabUI` is a 2599-line, ~245-field god-object across 18 partials**, orchestrating 13
  subsystems; `partial` hides a god-class, it doesn't separate concerns. `AttachClouds` is a
  137-line deferred god-method doing all wiring + ~40 CLI overrides inline, where load-bearing
  "last-wins" ordering is line-order-dependent. **The single unit that will resist the Phase-B
  refactor.**
- **`terrain_lab.gdshader` is a 1064-line monolith** carrying ~6 parked default-off subsystems
  (distance detail, GM2 height+POM, macro color, GM3-A, Unit-4 breakup, splat path), a full custom
  `light()` BRDF, and **`zone_weights` duplicated into `splat_weights.glsl` that has already
  drifted** (gdshader multiplies `band_soft_mult`, the glsl copy doesn't). Only `hex_contrast` is
  truly dead; `hex_rot_strength` *is* live via the AO path.
- **`CloudVolume.cs` (691 lines) is ~40% sun/moon/stars/atmosphere/cirrus pass-through** unrelated
  to volumetric clouds — extract a thin `SkyMaterial` facade before the atmosphere lane adds more
  uniforms.
- **God-ray cloud-shadow occlusion (occ_mode 3) is wired but never enabled** (default is luminance
  occ_mode 2) — `SetShadowTexture`/`SetCloudAltitude`/`sun_cloud_gate` is dead at runtime.
- **`GodRayTest.cs` + `scenes/godray_test.tscn` is dead scaffolding**; `lab_experiment.tscn` is a
  near-duplicate orphan.
- **`MaterialBoard` judged the 738→108 under a *different* shader than the terrain, and mis-binds
  height→AO** — the curated library reflects a look the terrain doesn't render identically. Worth
  knowing as the texture lane goes live.
- **~37 hardcoded absolute-path `GetNode("/root/...")` lookups** couple every lighting method to one
  fixed scene tree (and run per-frame in the hot path — the documented, still-open backlog item).
- **`FieldParams.Load` uses `GetProperty` (throws) for all 29 keys** — a typo in the most important
  JSON hard-crashes lab startup, even though the project already guards the *hot-reload* path.
  Latent (keys match today).
- **Doc sprawl returned:** 152 `.md` files; `docs/archive` (43) + `docs/superpowers` (32) now
  *larger* than what the reset cleared. `HANDOFF.md` is stale (still says "both lanes PAUSED"); 5
  untracked `.cs.uid` meta files risk fresh-clone script-registration.

## 🕳️ GAPS — missing, and the next lanes will need it

- **The combined eye-gate session itself is the biggest gap.** It's what the 06-20 reset was built
  around and it hasn't been run; the un-gated stack (AT-1, AT-2, clouds CO-3/CO-4, GM1/GM2/GM3-A)
  only grows.
- **N-suns / N-moons (roadmap C3) is not reachable without a refactor.** [gap, sev 3] Single-
  luminary assumptions are baked deep into both `ComposeLighting` and `cloud_sky.gdshader`. Needs a
  `List<LuminaryState>` + uniform-array loop — budget it as a refactor, not an additive unit, before
  C3.
- **The owed Shadow & Lighting pass is unbuilt** — CSM/cascade tuning, PCSS soft shadows, SSIL
  re-check are roadmapped, none built. [gap, confirmed]
- **The surface-depth interface for the texture lane is undecided.** GM2 "POM" shifts only
  UV/world-XZ (no depth write, no silhouette); the height channel consumes a per-material *relief
  proxy*, not real geometric displacement, and erosion/hydrology is scoped *out* of the current
  ground reset. **If the height/displacement interface isn't co-designed up front, the texture lane
  gets rebuilt again when erosion/water starts.**
- **No headless correctness gate is possible.** `FieldCompute` NullRefs on
  `CreateLocalRenderingDevice()` under `--headless` with no guard — blocks any CI/smoke lane.
- **AT-2 has no measured cost**, and the perf budget (9.6 ms) predates both atmosphere passes — the
  budget being planned against is optimistic.
- **Weather axis (deferred) won't bolt on cleanly** — `Overcast()` uses `coverage³`, not the
  already-computed-but-unused baked weather field (`_weatherMean`), and the cloud layer buffer has
  no reserved slots, so adding weather forces a fragile synchronized 3-shader stride bump.
